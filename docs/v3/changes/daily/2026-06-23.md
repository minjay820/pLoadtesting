- Added env-driven Django admin-host hardening settings for downstream protected admin host deployments.
- Preserved current defaults when admin settings are unset: no trusted CSRF origins, no secure proxy SSL header, no forwarded host use, non-secure cookies, cookie path `/`, and no static root.
- Added parsing support for `DJANGO_CSRF_TRUSTED_ORIGINS`, `DJANGO_SECURE_PROXY_SSL_HEADER`, `DJANGO_USE_X_FORWARDED_HOST`, `DJANGO_SESSION_COOKIE_SECURE`, `DJANGO_CSRF_COOKIE_SECURE`, `DJANGO_SESSION_COOKIE_PATH`, `DJANGO_CSRF_COOKIE_PATH`, and `DJANGO_STATIC_ROOT`.
- Kept `DJANGO_ALLOWED_HOSTS` as the existing comma-separated host list source.
- Added WhiteNoise static serving support and build-time `collectstatic` output at `/app/staticfiles` so future admin-host deployments can expose only scoped Django admin static assets.
- Documented that admin host exposure still requires a separate access-control policy, scoped static route, owner-approved private runtime gate, and deployment smoke.
- Added unit coverage for env list parsing, boolean parsing, secure proxy header parsing, invalid proxy header rejection, and optional static-root parsing.
- No runtime route, Cloudflare DNS, private config, admin user, worker, scheduler, target-app, database, image publish, or deployment action was performed.

## Install Baseline and Initial Admin Bootstrap

- Documented the pLoadtesting database baseline: sqlite remains supported for local development, demos, single-node basic installs, and no-env validation; PostgreSQL remains required for production, multi-user operation, long-lived history, and worker/scheduler deployments.
- Added a one-shot `create_initial_admin` Django management command for first-install admin bootstrap.
- The command creates a staff/superuser only when no superuser exists, refuses to overwrite or promote existing users, validates the password with Django validators, and does not print the password.
- The command accepts `--password-file`; on POSIX it rejects files readable, writable, or executable by group/other users. Production use should provide an ignored private `600` password file.
- Confirmed that first admin creation is a DB-write lifecycle gate and must remain separate from route/runtime gates; no default credentials are shipped.
- Added tests for initial admin creation, refusal when a superuser already exists, insecure password-file rejection, sqlite fallback settings, and PostgreSQL URL settings behavior.
