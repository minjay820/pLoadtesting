## Summary

- No-compatible-worker root cause: Core dispatch selects from the persisted worker registry, not process smoke output. A worker must register and heartbeat into the same Control Plane runtime with `status=online`, `active_task_count=0`, and a matching engine capability before Core can dispatch a safe demo task.
- Deployment root cause confirmed in bounded integration smoke: worker registration can be rejected with HTTP 400 when Core `DJANGO_ALLOWED_HOSTS` does not include the host name used in `CONTROL_PLANE_URL`.
- Worker registration now supports `WORKER_PORT`, `WORKER_CAPABILITIES`, and optional `WORKER_ADVERTISE_IP` in addition to `CONTROL_PLANE_URL`, `WORKER_NAME`, and `PLOADTESTING_API_TOKEN`.
- The default compose worker service now declares `WORKER_PORT=8100` and `WORKER_CAPABILITIES=k6,jmeter`.
- Safe demo task dispatch still moves to `dispatched` only after worker HTTP delivery succeeds; no worker keeps the task `pending` with a diagnostic.
- The Worker Agent now posts `execution_status=running` through the protected result callback route when execution starts.
- Core accepts the protected running callback without creating a `TestResult`, sets task `status=running`, and fills `started_at`.
- Final protected callbacks still persist results and move tasks to `completed` or `failed`.
