## Summary

- Deleted the unused `WritePrecision` import from the optional InfluxDB client import block in `workers/agent.py`.
- Added a `Collect Control Plane diagnostics` step to CI that prints the Python version, pip version, installed package list, and `python manage.py check` output before `python manage.py test apps/ --verbosity=2`.
- Updated the Control Plane job to use `DJANGO_SETTINGS_MODULE=config.settings`, which matches `control-plane/manage.py` and the repo's active settings module.
- Documented the new CI diagnostics flow in an active runbook and linked it from the runbooks index.
- Added a domain-level system overview that combines functional requirements, current API surface, core data model, and runtime architecture into one reader-facing document.
- Updated the docs trunk index so today's daily log is reachable from `docs/v3/README.md`.
- Added seven local target apps covering baseline, latency, error, payload, resource, CRUD, auth-like, and business-flow scenarios.
- Added target manifests and a loopback-only compose file so the suite is locally reproducible without external services or credentials.
- Added pytest smoke coverage for manifest loading, `/health`, safe-limit enforcement, and README/compose consistency.
- Updated the root README and system overview so repository-level orientation reflects the new target suite without removing the original `target-app/`.
- Added engine sample assets and profile metadata so target apps can be selected through template-driven task creation instead of only hand-written `engine/script_path/target_url`.
- Added a Control Plane registry that reads local manifests and task templates, exposes template catalog data, and resolves template-based task creation into the existing task model fields.
- Documented the current recommendation to defer gRPC until there is a real need, prefer SSE before WebSocket if streaming is needed quickly, and keep DB/file/auth-heavy expansions bounded and disposable.
- Implemented SSE as the first streaming target because it stays within the existing HTTP stack, is finite by design, and is cheap to validate in CI compared with WebSocket or gRPC.
- Added a portable smoke script that exercises real Docker build/run behavior and always tears the compose stack down, even after failures.
- Extended the SSE target with a progress-heavy profile that keeps streams finite while increasing per-step metadata density for progress-oriented workloads.
- Added a bounded WebSocket target with echo and broadcast behaviors, but kept it local-only and capped so runtime validation stays predictable.
- Added a SQLite-backed DB-heavy target that auto-initializes and seeds a disposable dataset without introducing any external database service.
- Extended `payload-api` instead of adding a separate file target so file-heavy coverage stays within the existing payload family and reuses the current compose/runtime pattern.
- Extended the same payload target with archive-style and read-many flows while still keeping everything deterministic, bounded, and independent of the host filesystem.
- Extended `auth-flow-api` with token-use expiry and refresh semantics instead of adding real auth complexity, keeping the flow deterministic and secret-free.
- Extended the same auth target with cookie-session and MFA-like branches while still avoiding any real secret, external IdP, or nondeterministic second factor.
- Backfilled JMeter target coverage so every current target family now exposes at least one `k6` sample and one `jmeter` sample asset.
- Used parametric HTTP plans for simpler target families and JSR223 flow plans for SSE, WebSocket, auth-heavy, and DB-heavy targets where bounded multi-step logic is required.
- Corrected JMeter worker execution so template parameters are passed as runtime properties instead of only environment variables.
- Added a dedicated profile coverage matrix so exact engine parity can be tracked separately from coarse target-family coverage.
- Closed the previous exactness gaps for `crud-api`, `sse-api` ticker, and the main auth checkout and failure-branch flows.
- Extended `payload-api` beyond zip/read-many into tar-like package generation and manifest-driven selective subset flows while keeping deterministic caps.
- Updated the target-app compose file so each localhost host port can be overridden by environment variable, and changed the Docker smoke script to use isolated `18180-18189` ports by default so runtime smoke validation no longer collides with an already running local suite.
